# Atlas Agent v0.16.2

## Remote IT support

- Use `/support` to pair two Atlas installations over a local network or an
  operator-managed internet relay. Pairing codes expire, work once, and require
  the computer owner's approval and matching verification codes.
- Grant separate permissions for diagnostics, files, commands, screen viewing,
  pointer input, browser operations, installation, services, and restart requests.
  Permissions can be narrowed or revoked during the session.
- Remote browser, computer, and tool pipeline execution reuse Atlas's native
  tools on the supported computer. Every workflow step checks the owner's current
  permissions; reconnects cannot replay an operation with an unknown effect.
- File transfers support chunks, resumption, size limits, and SHA-256 validation.
  The support menu discovers accessible local drives without requiring folder
  input. Operating-system permissions still apply.
- Support menus expose active work, transfers, session history, and owner controls.
  Pairing alone does not activate the computer-use overlay or take over the cursor.
  Indicators appear during remote work and release control when the last active
  operation finishes; the connection remains ready for the next task.
- A banner stop revokes the session. Shutdown waits for active operations and
  banner callbacks to finish writing their session history.

## Reliability fixes

- Remote failures, interrupted mutations, and stale connections report their
  actual state rather than treating a successful HTTP response as task success.
- Screenshots travel as image parts instead of base64 embedded in model text.
- Remote workflow state remains in Atlas's private state directory rather than
  being written into an exposed drive.
- Named development builds skip release updates, preventing an npm update from
  renaming a development executable that npm will not replace in that directory.

## Validation scope

Automated support, transfer, native-tool, provider-contract, and interface tests
cover local transport and fixture scenarios. An owned headless Chrome fixture
exercises real browser execution. These results do not establish real-model
planning performance or acceptance across two physical PCs and an internet relay.

For setup and acceptance steps, see `docs/remote-support.md` and
`docs/remote-support-acceptance.md`.

Project knowledge: short, reviewable notes about how this project works, kept between sessions.

- `propose` (title, summary, body, sources): after you worked something out that a future session would otherwise re-derive (how the build or deploy works, why a design was chosen, where a tricky part lives), write it down. List the files it came from in `sources`. A proposal is not used until the user approves it; do not tell the user it is saved as if it were active.
- `list`: every note with its status; stale ones are marked.
- `read` (id): the full note. If it is marked STALE, check it against the code before trusting it.

Do not propose anything that is already obvious from the code, temporary task state, or anything containing credentials.

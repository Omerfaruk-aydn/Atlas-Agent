Keep a ledger of problems you find while working, so none is forgotten or declared fixed without proof.

- `add` with `title`, `severity` (minor, major, critical) and `where`: record a problem the moment you find it, including ones in code you were not asked to change.
- `close` with `id`, `command` and `output`: only after you ran a command that shows the problem is gone, pass that command and the relevant part of what it printed. A claim like "fixed" without both is refused.
- `list`: see every issue, open ones first.

The task cannot be finished while a major or critical issue is open. If you decide not to fix one, say so in your final answer instead of closing it.

# animated-mascots

Use this procedure only for an assignment whose deliverable needs it. Read the
actual role contract, owned paths, user constraints and current tool descriptions.
The role's preferred skill binding is a starting recipe, not additional access.

## Capability and input preflight

- Identify the exact source, reference, requested output and acceptance criteria.
- Inspect available native tools, permitted commands and connected MCP schemas.
- Check optional runtimes/renderers with scoped commands before depending on them.
- Preserve user references, repository conventions and unrelated working changes.
- Existing authentication and permission/hook controls apply to every action.
- Report missing capability precisely; continue independent authorized work.

## Domain procedure

1. Resolve character reference, intended application, art direction, display size and supported animation states.

2. Use an available authorized image/animation tool or project-native drawing backend. ChatGPT pet services are not assumed available.

3. Define a stable character identity, silhouette, palette, anchor points and consistent proportions across frames.

4. Plan idle, working, success, failure, attention and interaction states according to the actual product; document any directional variants.

5. Keep sprite layout, frame dimensions, alpha handling, frame rate and transition semantics in an explicit manifest.

6. Inspect every state for cropping, seams, inconsistent scale, unwanted background and jumps between frames.

7. Verify animation timing and loop boundaries in a real preview, including pause, reduced-motion and shutdown behavior.

8. Avoid continuously distracting motion during reading. Provide an immediate static/reduced-motion state.

9. Preserve editable source and original references. Generate replacement assets separately until validated.

10. Use stable local asset identifiers instead of temporary transport URLs. Package only files owned or authorized for the project.

11. Validate the manifest against actual sheet bounds and frame count; missing states remain unavailable rather than silently substituted.

12. Deliver source assets, preview, manifest, state coverage and actual observed checks. No upload, pet activation or publication is implied.

## Asset and animation brief

Use only when the product needs an animated mascot or character asset.
Define identity, intended size, background/transparency, supported states and
target application's actual asset format. A decorative mascot is not a replacement
for a status control or accessible message.

Inspect existing artwork and obtain a consistent silhouette, proportions,
palette and anchor. Preserve user-supplied character requirements and identify
which assets are editable source versus rendered exports.

## State and frame construction

Define the states relevant to the target: idle, attention, working, success,
error or transitions only when requested. Specify event, duration, repeat rule,
entry/exit and interruption. Do not copy another host's fixed state inventory
when Atlas uses a different runtime contract.

Keep anchor and bounding-box behavior consistent across frames.
Check transparency edges, clipping, sprite indexing and frame order.
For directional assets, preserve orientation and visual identity across views.

Use vector/code-native construction for editable geometric assets, or an actually
available image-generation capability for requested raster artwork. Do not claim
a generator exists because a cached skill names one.

## Runtime and accessibility acceptance

Exercise idle loops, rapid state changes, cancellation and scaling.
Transitions should begin from the appropriate current state without a flash
or jump caused by inconsistent anchors. Respect reduced motion with a stable
informative alternative.

Verify source dimensions and scaling in the intended application.
Inspect light/dark backgrounds where transparency is involved.
A contact sheet proves frame appearance, not smooth playback.

Example: a working-to-success transition must not reset the character position
when the sprite changes. Preview the animation, inspect the anchor and confirm
the state event drives the correct sequence.

Deliver source assets, state manifest or integration appropriate to the real
runtime, preview evidence and requested exports. Do not claim ChatGPT pet
upload/activation without the actual authorized service capability.

## Verification and recovery

Bind each important criterion to a real check and a navigable artifact or source.
Distinguish fresh executed results, cached results, structural checks, inspected
renders, skipped checks and user-reported observations. When a prerequisite fails,
stop dependent actions and retain the first failure, current identity and recovery
options. Retry within bounds only after identifying a relevant changed condition.
Do not repeat uncertain writes, suppress failures or fabricate missing evidence.

## Delivery

Return the assignment's requested output schema. For workflow tasks use the Atlas
JSON handoff with actual changed_files, checks, dependencies, risks and decision.
Include artifact paths and source provenance in evidence. A ready handoff is a
reported result for coordinator verification, never authenticated completion.
In quality-only runs do not implement fixes, change tests or certify unseen output.
